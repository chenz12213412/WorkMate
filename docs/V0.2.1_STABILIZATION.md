# WorkMate V0.2.1 Stabilization

## P1 Checkpoint 范围

本检查点只包含任务书 S1～S5。H1～H8 属于 P2，等待 P1 验收后再实施。

## S1：离散事件守恒

`ActivityAggregator` 会先按 5 分钟边界和午夜建立全部时间片，再使用 Largest Remainder Method 分配键盘、鼠标点击、滚轮和应用切换事件。每段先取比例结果的整数部分，剩余事件按小数余数从大到小分配；余数相同时按时间顺序决定，因此结果确定且总数严格等于原始 Sample。

鼠标距离、活动秒数、工作秒数和分数权重仍按时间比例拆分。

## S2：WorkMate 自身前台处理

Foreground Hook 不再跳过自身进程。WorkMate 成为前台时会立即结束上一个外部应用的 Foreground 区间，但 `ApplicationProcessPolicy` 会阻止 WorkMate 进入 AppUsage、TopApplications 和 DominantProcess。

AppSwitch 的用户语义为“标准化后的外部 ProcessName 变化”。WorkMate 是透明中间状态：Chrome → WorkMate → Visual Studio 计一次，Chrome → WorkMate → Chrome 不计切换。

窗口标题仍只存在于瞬时内存快照，不写入数据库。

## S3：系统状态串行化

`ActivitySnapshotService` 的 Tick、系统可用性转换、Flush 和持久化共用同一个 Semaphore。Lock/Suspend 会先停止 Timer，等待当前操作结束，采集最后一个有效时间片，持久化 Dirty Bucket，然后重置连续工作和强度。Resume/Unlock 会清理不可用期间残留、重置鼠标位置与采样起点，再恢复 Timer。

`SystemActivityStateMonitor` 按收到的事件顺序排队转换。只有 `!locked && !suspended` 时才恢复活动采样，避免 Unlock while suspended 错误启动 Timer。

Snapshot 回调在释放 Activity Semaphore 后触发，避免 UI 或提醒回调进入串行门造成死锁。

## S4：Stand Reminder 周期

站立提醒使用独立 `StandReminderCycle`，不再依赖 Dashboard 的 ContinuousWorkDuration 作为一次性开关。符合条件的 Active 秒数达到阈值后提醒；点击“我起来了”才开始新的完整周期。Snooze 保持当前周期为待处理状态，AFK、午休、下班、Sleep、Lock 和 LAB 会重置周期。

ContinuousWorkDuration 的产品定义没有改变。

## S5：工作强度隔离

ActivityScore 对所有有效电脑活动计算。WorkIntensity 只在 WorkCategory 为 Normal、Overtime、Lab 或 Meeting 时累积独立权重和样本秒数。WorkCategory.None 不进入 WorkIntensity 分母。

Dashboard 在上班前、午休或下班后且未进入有效工作模式时显示空强度；Sparkline 只选择包含有效工作秒数的 Bucket。

## 回归检查

- 1 / 3 个键盘事件跨 Bucket 守恒。
- 鼠标点击、滚轮、应用切换跨 Bucket 和午夜守恒。
- WorkMate 不进入 AppUsage，外部应用切换语义正确。
- Lock、Suspend、Unlock、Resume 组合状态正确。
- Tick 与 Lock 并发执行不抛异常且最终发布 AFK Snapshot。
- Stand 完成后可以进入下一周期，Reset 会丢弃旧周期。
- Lunch/OffWork 活动保留 ActivityScore，但不产生 WorkIntensity；Overtime 恢复 WorkIntensity。

## 隐私边界

本次没有新增原始事件持久化。数据库仍不保存具体按键、输入文字、剪贴板、鼠标坐标历史、鼠标轨迹或 Window Title。

## P2：H1～H8

- H1：普通 Drink/Stand Snooze 使用 `reminder_history.next_due_at` 持久化。ReminderEngine 每 10 秒读取当前日期的 Snoozed 记录，重启后仍可恢复；超过 2 分钟宽限期会写入 `Expired`。
- H2：`ReminderAction.Preempted` 与 `ReminderHistoryStatus.Preempted` 独立于 Dismissed。Schedule Critical 抢占普通弹窗后，未过期的普通提醒重新进入队列。
- H3：AppSwitch 的标准化外部 ProcessName 语义由 P1 完成并继续受回归测试保护。
- H4：`WorkModeService.Snapshot` 在锁内生成不可变快照，采样 Tick 使用同一份 ActivityMode/Overtime，避免读取到混合状态。
- H5：核心后台服务的 Dispose 使用幂等状态门；取消优先于释放，避免定时器、语音和提示队列后台回调访问已释放 CTS、Semaphore 或引擎。
- H6：数据库初始化使用 `PRAGMA user_version` 的 1→2→3 顺序迁移，并在单事务中补充 `longest_continuous_seconds`、`shown_at`、`action`。旧数据库中的数据不被重建或覆盖。
- H7：`WorkMate.ScheduleChecks` 覆盖 Snooze 跨 Store 重启恢复、Preempted 状态、Schema Version、WorkModeSnapshot 和重复 Dispose；UI Capture 仍不属于默认测试路径。
- H8：`.github/workflows/build.yml` 在 Windows Runner 上执行 Restore、Release Build（warnings as errors）和 ScheduleChecks，不运行 UI Capture。
